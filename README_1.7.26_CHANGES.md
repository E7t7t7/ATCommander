Continues the functional 1.7.25 source. Earlier working combat, mail, training and bulk Nixon flows were preserved.

## Resizable logs and deck workshop (October 27)

- Events controls are vertically scrollable above a draggable divider, with a minimum visible activity pane. Larger control sections no longer push the log below the window. Shared activity panels, including Swole, add a separate resizable live-log window with a Follow latest switch and bounded rendering.
- Added a dedicated Deck builder page: exact saved-slot selection, verified in-game renaming, slot-to-draft loading, owned-card search, double-click to add, remove selected cards and a reviewed save. Renaming refreshes all Arena/event/defense/builder selectors while retaining their IDs.
- Suggestions support balanced recommendations, a single character with items, BGE/trait combo results and character-only decks. Controls cover 25–35 cards, rarity, PC count and researched-only recipes. Drafts contain unique owned card instances with current level stats; unavailable rules stop rather than silently broadening. Rankings are heuristic stats/coverage, not a claim of optimal battle performance.
- Deck edits wait for other automation, freeze the selected slot and preview stamp, re-read current ownership/state, keep a local recovery backup and transmit each write once. Renames and replacements verify names, hero/cards and active selection from fresh state; uncertain results require a refresh. Stop and closing wait for the worker, and widgets update only on the main thread.
- Read-only live previews used 1,134 current usable card instances and produced two unique 25-card drafts: balanced coverage 76.9%, single-character coverage 100%. No deck edits, purchases, battles or resource spending occurred during this check. Rename/save writes were tested against synthetic accounts only; no live rename or replacement is claimed.
- All **1,335 offline tests** pass, with 26 new checks for deck generation, ownership/research/trait rules, guarded rename/save, lost replies, stale previews, name preservation, optional catalog failure, shared selector updates, and log visibility/resizing. The full twelve-tab interface constructs successfully. Existing Melee settings and battle behavior remain covered.

## Adventure capped-farm recovery (October 19)

- A saved move for a mastered default farm could pause every restart because its mastery counter was already capped. Native startup reads `battle_to_resume` (default zero) and only retains previous combat data when `active_battle_data` is present; resuming uses that local data, with no separate battle-status call.
- An accepted farm attempt can now be archived as an unknown outcome when fresh full account state has no native resumable battle, the mastered stage remains available with nonregressed progress, and at least two server minutes have passed. That delay is a conservative local guard, not a claimed server expiry time. No win, loss or item/energy spending is inferred from this recovery.
- Start intents without an accepted battle, incomplete island routes, active/malformed resume data, recent requests and contradictory progress remain blocked. The checked record must still match when archived, so recovery cannot clear a newer request. The last eight unknown-attempt records and a cumulative count survive later normal journal writes; no battle/session/authentication identifiers are stored.
- Adventure finished events retain a pause reason. The GUI preserves pause/error details through completion events and refreshes, says “run finished/stopped” for ordinary endings, and does not schedule retries after a safety failure. Saved farm and Continuous monitor preferences are retained.
- All **1,210 offline tests** pass, including **33 new recovery/status checks** and **135 Adventure tests** in total.

- New Queue reconciles a pending request before considering queue replacement. Recovery also runs before comparing changed settings, so editing a budget cannot prevent checking an older action. Older saved queues remain compatible with the new default-off option.
- If a pending speedup's exact pair is already researched and no live task conflicts, inventory replenishment need not block the queue forever. The request is archived as an unverified spend, its reserved hours are retained separately from confirmed spending, and it is never replayed. Still-active or contradictory targets remain blocked. Recovery history survives an explicit New Queue.

A strict timer reduction can still confirm when the server clamps completion to a fresh time just after dispatch. Fresh compact reads cannot retain old inventory mirrors or ad counters as verification evidence, and a Stop before dispatch releases only an intent known not to have been sent.
- All **1,177 offline tests** pass, including **34 new Research recovery/control tests**. The actual Tk controls were built without showing a window to verify saved all-mode settings and disabled conflicting spending controls. No additional research items were spent by these checks.
